# DNF GM

DNF 私服（服务端）的 GM 工具。C 语言，Windows 原生界面，单个 exe，不依赖运行时或第三方库：
MySQL 协议、PVF 解析、zlib 解压均为自带实现。

## 功能

- **角色**：等级、职业/觉醒、金币、复活币、点券、SP/TP、QP、疲劳、PVP 段位、改名、克隆
- **物品**：编辑 6 个容器（物品栏 / 穿戴 / 宠物 / 仓库 / 珠宝 / 账号金库）；按编号或名称查询、批量发放；扫描并清除错误物品
- **连续取码**：读游戏内鼠标悬停的物品编号，自动整行追加到发放队列（默认开启，也可用热键）
- **邮件**：收发、删除、附件
- **宠物 / 时装**：编辑列表，清理无效记录
- **任务**：放弃、标记完成、补发材料、清空
- **活动 / 封停**：活动启停、封停解封、重置密码
- **泡点**：按间隔给在线账号发点券 / D 点 / D 币 / 物品，可限定人群与时长
- **备份**：整库或单角色导出 SQL，可还原；长任务有模态进度窗（可取消、可转后台；工具栏不再单独占一个取消按钮），
  还原前自动整库备份；取消或失败时回滚当前事务。DDL 与 MyISAM 写入不支持整体回滚
- **PVF**：只读解析，显示真实物品名（未加载时显示为 `#编号`）

在线金币、复活币、补满疲劳和 SP/TP 支持 Native 与原版 Linux 的同一游戏端桥接：修改游戏内存、推送客户端，
确认原游戏存档后才报成功；快捷增加按实际余额递增。金币超过原游戏的等级／PVF 上限时拒绝，
不截断发放；数值上限为 2147483647。其他缓存角色数值仍需退出游戏。
Native 在启用 DP2 后自动准备；Linux 的安装步骤见
[桥接说明](https://github.com/zmbksyyr/dnf-native/blob/main/docs/README.md#gm-在线金币复活币与疲劳)。
无需 Robot 或新端口，桥接不可用时明确拒绝在线修改。
金币使用独立 v2 队列，疲劳使用 v3，SP/TP 使用 v4；升级时须同时更新 GM 与游戏端 helper，旧版桥接不能处理新增操作。
疲劳按游戏原接口读取的基础与额外上限补满，清除已使用计数；离线按角色上限补满基础疲劳并保留额外疲劳。
固定原 ELF 的 `charac_stat.fatigue` 是剩余疲劳；旧实现清零的判断有误，现已修正。
“满 SP/TP”设置四组计数为 65535，在线调用原技能通知和存档接口，保留已学技能与技能指令。
原协议每组只有 16 位，旧值 90000 实际传成 24464；在线与离线均拒绝超出 0..65535 的输入。

“仅在线”泡点只发给当前游戏角色；登录表残留在线标记或停留在选角界面的账号，
经游戏端确认没有当前角色后跳过，不中断其他玩家发放。桥接故障、超时和不确定结果仍会停止发放。
全服/指定账号复活币如包含在线账号的多个角色，
会在提交前拒绝，需退出该账号或选择仅在线；保存失败、超时等可能产生部分到账，
界面会显示实际结果并停用泡点，核对后再处理，不能直接重发整批。
搜索按钮查询数据库，支持角色编号，不限于首次载入的名单；轮询保留已提交的搜索条件。

## 构建与回归

```
tools\build.bat            # 需要 zig；产物在 ..\_build\DNF_GM_C\
python tools\regress.py    # 回归套件，见 tools\README.md
```

详细说明见 [`tools/README.md`](tools/README.md)。
