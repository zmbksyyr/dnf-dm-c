# tools —— 本地编译与回归脚本

这里的两个东西都只服务于**开发机**，不参与发布：

- `build.bat` —— 本地编译，产物落到项目目录之外
- `v_*.py` —— 回归脚本，启动程序、模拟操作、断言结果

发布产物由 `.github/workflows/build.yml` 手动触发构建，与本目录无关。两边的编译参数（`-std=c11 -O2 -DNDEBUG -DUNICODE -D_UNICODE -static -s`）保持一致，改一处记得改另一处。

## 编译

```
tools\build.bat
```

双击或在任意目录下调用都可以——脚本用自身位置推项目根，不写死盘符。

**产物在项目目录之外**：

```
<项目根>\..\_build\DNF_GM_C\
├─ DNF_GM.exe      编译结果（静态链接，可直接拷走运行）
├─ res.obj         中间产物
├─ config\         程序运行时自建（settings.ini / 备份 / 日志 / 缓存）
└─ shots\          回归脚本截的图
```

仓库里因此不会出现 exe、obj、config、截图，`git status` 永远是干净的。

**zig 的查找顺序**：环境变量 `ZIG` → `PATH` 里的 `zig` → `C:\zig\zig.exe` → `%LOCALAPPDATA%\zig\zig.exe`。都没有就报错退出。

**两个可选环境变量**：

| 变量 | 作用 |
|---|---|
| `ZIG` | 指定 zig.exe 的完整路径 |
| `DNF_GM_BUILD` | 改输出目录（默认 `..\_build\DNF_GM_C`）；`pages.py` 会跟着用同一个值 |

程序正在运行时无法覆盖 exe，脚本会直接提示先关掉，而不是丢一句链接失败。

## 回归脚本

「回归」= 改完代码，回头验证原来能用的功能现在还能用。这些脚本不是单元测试，它们**真的启动程序、真的发消息点它**，然后读回控件文本、日志、控件矩形，或直连 MySQL 查库来断言。

```
python tools\v_gmwrite.py
```

跑之前先关掉已经在运行的 `DNF_GM.exe`（脚本会自己起一个，起完自己杀）。

**前置条件**：Python 3 + `pip install pillow pymysql`，以及一个能连上的测试库。数据库参数从 `<产物目录>\config\settings.ini` 读（程序自己写的那个），读不到就用代码里的默认值——改过库密码只需要改配置，脚本不用动。

| 脚本 | 验什么 |
|---|---|
| `v_gmwrite.py` | GM 页改金币 → 失焦 → 落库 → 改回原值 |
| `v_queue.py` | 金币/复活币/点券/等级四个字段连改，一个都不丢 |
| `v_stable.py` | 物品页选中与滚动扛过一次 reload；写库期间界面不把输入框的值顶回去 |
| `v_pollcard.py` | 外部改等级后：左栏卡片跟着变、GM 表单保持快照、物品页选中不丢 |
| `v_pageall.py` | 11 个页签逐个进入并切回，查有没有整块空白（控件没画出来） |
| `v_geom.py` | 量控件矩形，查越界、重叠、两栏底部是否齐平 |
| `v_left.py` | **左栏在不在**：角色卡/资料卡是主窗口的直接子控件，不在页签里，`v_geom` 看不到。`do_layout` 里漏调一次 `left_layout()` 整栏就停在初始位置甚至消失，而其余回归照样全绿 —— 出过一次，所以单独盯 |
| `v_top.py` | 顶部一行：两个目录输入框等长、两个按钮等长、整行右端与下方列表右端对齐（基准取页签里可见列表的右端，不复用布局里的算式） |
| `v_tab.py` | Tab 键能否走到每个输入框，卡片内顺序是否正确 |
| `v_align.py` | 量 PVF 标签与页签「物品」的左边缘差几像素 |
| `v_selfcheck.py` | 临时把 `taiwan_cain_2nd.letter` 改名，验证启动自检能报出缺表（`finally` 里改回） |
| `v_norow.py` | 造「表里没有这条记录」的场景，验证报错而不是报成功 |
| `v_bubble.py` | 临时把账号置为在线，验证泡点按间隔加点、关掉就停（点数和在线状态都复原） |
| `v_features.py` | **GM 页全功能自测**：把值改脏 → 点按钮/提交表单 → 验有没有被改回（16 项，值一律复原）。一键与表单各功能真实落库与否全靠它兜底 |
| `v_grabauto.py` | 连续取码机制：热键开启（发放页没打开过时要能自动建出来）、写盘、复选框同步、无悬停时队列不动、热键来回切；`--hover X,Y` 跑实机用例（悬停即采、采到即入队、同编号去重） |
| `v_hover.py` | 编号悬浮卡：悬停列表的编号行 400ms 浮出「图标 + 详情」，换行换内容、移开收起。要真鼠标（`SetCursorPos` 会被真实输入抢回去，脚本会高频按住并回读坐标），还要 PVF 旁边的 `ImagePacks2`；本机光标被占用时标「跳过」而不是假失败 |
| `v_listtip.py` | **列表上不许挂提示**：绑了编号卡的列表若再挂 `ui_tip()`，悬停行时两个气泡会撞。静态扫 `src/*.c` 查「既挂 tip 又 bind」的组合（覆盖弹窗里的列表，运行时进不去），再运行时悬停三个列表第一行确认屏幕上不出现 `tooltips_class32`。没绑编号卡的列表（泡点计划）不受限 |

`pages.py` 是公共库，脚本里只留各自的用例，重复的东西一律往这里收：
启动并连库（`start`）、按编号找控件（`ctl`）、读文本（`txt`）、改文本（`set_text`）、
失焦提交（`blur`）、投递点击（`press` / `click_at`）、数列表行数（`rows`）、
断言（`check`）、等条件（`wait_until`），外加截图、切页签、等主窗口、`db()` 连库。

## 写新脚本的几条红线

都是踩出来的，违反一条症状都很难查：

1. **不要给跨进程消息传指针**。系统只对 `WM_GETTEXT / WM_SETTEXT / WM_COPYDATA` 等少数消息做内核封送，控件自定义消息（`WM_USER+n`）没有——指针原样进目标进程的窗口过程。`LVM_GETITEMTEXT` 会直接把被测程序打崩；`SB_GETTEXTW`（读状态栏）更阴：不崩，但会把对方的堆写花，之后 `GetWindowRect` 莫名失败、复选框时对时错。**读界面状态用 `WM_GETTEXT`（Edit/Static/ListBox）或读日志，别读状态栏。**
2. **`BM_GETCHECK` 是 0x00F0**。0x00F2 是 `BM_GETSTATE`，带焦点位（0x8），复选框一有焦点返回值就是 9，`== 1` 永远不成立——症状是"勾选态和实际反着来"。
3. **最小化恢复是异步的**。`ShowWindow(SW_RESTORE)` 之后立刻取控件矩形/句柄不可靠，至少等一秒。
4. **采样列表行坐标别按固定偏移猜**。列头是个独立的子窗口（SysHeader32），
   行区要从它的底边往下算（`LVM_GETHEADER` + `GetWindowRect`）。直接写
   `top + 24` 之类的估算会把采样点落进列头里，而列头那一行不是数据行、
   不弹编号卡片 —— 看起来就像悬停没反应，其实是测错了位置。
5. **别指望靠改窗口尺寸触发重排**。主窗口大小被 `WM_GETMINMAXINFO` 锁死，
   `SetWindowPos` 改不动，首帧布局就是唯一一次布局 —— 想验「缩放后还对不对」
   是验不到的，只能验首帧。
6. **找页面里的控件要从 `DnfPage` 下探一层**。`EnumChildWindows` 只枚举直接
   子级，而页面容器是主窗口的直接子窗口（不是页签的），列表又挂在页面下面。
   直接从主窗口抓第一个 `SysListView32` 会撞上左栏的角色列表。
7. **列表上不要挂 `ui_tip()`**。绑了编号卡的列表悬停时会弹卡片，再挂一条
   说明气泡就跟它抢位置（整块悬停都弹会直接撞；改成只在列头上弹，边界上还是会
   撞）。列表的用法说明统一写成列表下方一行常驻小字，让列表少一行给它。
   守卫是 `v_listtip.py`。
8. **发放物品要按槽位分区落槽**。背包不是一整条：装备 / 消耗品只落普通栏
   （0..152），材料 / 任务材料只落材料栏（153..248）。放错区服务端
   `InventoryVerify` 直接判整个背包非法并断开连接，而且一次只打一条
   `ERROR_ITEM_LOG`（`error_line(5624)`）—— 删掉那一件只会让报错顺延到下一件，
   极易误判成"不是物品的问题"。分界是从原生数据里量出来的，别猜。
9. **角色归属的表集要运行时发现，不能写死清单**。扫
   `information_schema.COLUMNS` 找带 `charac_no` 的表，比手写一份可靠 ——
   写死的那份漏了 11 张，克隆出来的角色看着正常、进游戏就被服务端踢，
   界面上一点征兆都没有。反过来说，带 `m_id` 的表**必须**手工白名单：
   那一列只说明属于某个账号，里头混着封停记录、建角限制、计费数据，
   自动扫出来再复制过去等于把封号一起克隆。
   日志 / 流水 / 回收站 / 审核镜像表（后缀 `_log` `_del` `_history` `_backup`
   `_bak` `_old` `_mod`）一律排除：行数动辄几百万，复制过去既没意义，
   又会把备份文件撑爆、把克隆事务拖到超时。

## 几个约定

1. **会改库，但会复原**。`v_gmwrite` / `v_queue` / `v_stable` / `v_pollcard` 都记录原值并写回；`v_pollcard` 还会把等级改回去。跑完仍建议对一下 `money` / `coin` / `cera` / `lev`。
2. **`v_selfcheck` 会临时改表名**。它把 `letter` 改成 `letter_selfcheck_bak` 再改回来，中途程序会报缺表——这是预期结果。异常退出时表可能留在改名状态，手动改回即可。
3. **`v_bubble` 会临时把账号置为在线**，并在 `finally` 里把 `cera_point` 和 `login_status` 都改回测试前的值。它只认 `account=1`，换库要改脚本顶部的 `M_ID` / `ACC`。真有人在线时也能跑，但会短暂改动他的赠送点券。
4. **`v_grabauto` 用真实按键按热键**（`keybd_event`，系统级信号，不是发给某个窗口的）。脚本每次按之前先把程序最小化——程序只在前台不是自己时才认这个键。跑的时候别在游戏里做重要操作。RDP 会话断开/锁屏时合成按键送不进被测程序，热键与 `--hover` 用例会自动跳过（脚本自检输入桌面，不假失败）。
5. **不要在 CI 里跑这些**。它们要真实 MySQL、要能创建窗口、而且会改业务数据，都跑在开发机上。
6. **控件 ID 是硬编码的**（`pages.PID(page, n) = 1000 + page*100 + n`）。界面改了就跟着改，所以脚本天然短命——只有经得起反复用、改界面也愿意同步维护的才留在这个目录。
